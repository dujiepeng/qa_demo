# 好友页与黑名单页设计

## 背景

当前项目已经存在真实好友列表页 `SingleChatListPage`，并且 SDK 侧具备联系人与黑名单管理能力。  
本轮需求不是再新增一个“黑名单测试页”孤立入口，而是补齐更符合业务心智的两个页面：

- 好友页：展示好友列表，并支持将好友加入黑名单
- 黑名单页：展示黑名单列表，并支持将用户移出黑名单

同时，这两个入口需要同时出现在：

- 手机端功能列表
- Pad 端首页功能区
- Pad 端快捷入口区域

## 目标

- 手机端功能列表新增 `好友` 与 `黑名单` 卡片
- Pad 端首页功能区新增 `好友` 与 `黑名单` 入口
- Pad 端再增加一层快捷入口，便于直接跳转
- 好友页基于真实 SDK 好友数据
- 黑名单页基于真实 SDK 黑名单数据
- 好友页长按好友可加入黑名单
- 黑名单页长按用户可移出黑名单
- 复用现有好友页的视觉风格和交互节奏，避免重新造一套页面体系

## 非目标

- 不在本轮加入好友申请列表
- 不在本轮加入好友详情页
- 不在本轮扩展复杂批量操作
- 不将联系人模块整体重构为大型独立子系统

## 方案概览

采用“复用现有好友页 + 新增黑名单页 + 手机/Pad 双端接入”的轻度重构方案。

### 核心思路

1. 现有 `SingleChatListPage` 正式视为“好友页”
2. 在该页长按菜单中增加 `加入黑名单`
3. 新增 `BlackListPage` 展示黑名单列表
4. 新增统一路由：
   - `/friend_list`
   - `/black_list`
5. 手机和 Pad 共用同一套页面实现，不做平台分叉

## 页面设计

### 好友页

继续基于 `SingleChatListPage` 实现，保持当前已有能力：

- 获取好友列表
- 下拉刷新
- 添加好友
- 点击进入单聊
- 长按操作

长按菜单升级为：

- `复制 ID`
- `删除好友`
- `加入黑名单`

`加入黑名单` 的行为：

- 调用 SDK 联系人管理器的黑名单接口
- 操作成功后展示 `SnackBar`
- 刷新好友列表

### 黑名单页

新增独立 `BlackListPage`，视觉风格尽量与好友页一致：

- 顶部标题 `黑名单`
- 列表区域展示黑名单用户 ID
- 支持下拉刷新
- 空态文案 `暂无黑名单用户`

长按菜单：

- `复制 ID`
- `移出黑名单`

`移出黑名单` 成功后：

- 展示 `SnackBar`
- 刷新当前列表

## SDK 数据来源

### 好友页

继续沿用现有联系人接口：

- 获取好友列表：`contactManager.fetchAllContacts()` 或当前页已使用的等价接口
- 删除好友：`contactManager.deleteContact(...)`

### 黑名单页

黑名单页走 SDK 联系人管理器黑名单接口：

- 获取黑名单列表
- 加入黑名单
- 移出黑名单

实际实现时以当前工程可编译的 Flutter SDK 封装方法名为准，不强依赖底层 Java 命名。

## 入口设计

### 手机端

在 `PageMobile` 的功能列表中增加两张卡片：

- `好友`
- `黑名单`

点击后分别进入：

- `/friend_list`
- `/black_list`

### Pad 端

Pad 端增加两层入口：

1. `PagePad` 的功能区中新增 `好友` / `黑名单`
2. `HomePagePad` 的快捷入口区域增加 `好友` / `黑名单`

这样既满足首页功能区统一，又保留 Pad 端便捷访问。

## 路由设计

在 `main.dart` 中新增：

- `/friend_list`
- `/black_list`

其中：

- `/friend_list` 指向好友页
- `/black_list` 指向黑名单页

## 结构建议

### 保留

- `SingleChatListPage` 继续保留文件位置不变

### 新增

- `lib/pages/single/black_list_page.dart`

### 可选轻度抽取

若实现过程中好友页和黑名单页列表项重复较多，可轻度抽出一个私有列表项 builder 或小型公用 widget，但不做大规模联系人模块重构。

## 交互细节

- 长按菜单继续沿用当前页面风格，不引入新的复杂菜单框架
- 操作反馈统一用 `SnackBar`
- 用户 ID 复制逻辑复用现有实现
- 列表项点击行为：
  - 好友页：保持进入单聊
  - 黑名单页：本轮不进入详情，点击可不响应或仅展示 ID

## 错误处理

- SDK 请求失败时统一弹 `SnackBar`
- 页面销毁后不再执行 `setState`
- 刷新和长按操作均要做 `mounted` 判断

## 测试计划

- 手机端功能列表出现 `好友` / `黑名单` 卡片
- 新路由注册正确
- 好友页长按菜单包含 `加入黑名单`
- 黑名单页长按菜单包含 `移出黑名单`
- 黑名单页空态文案正常显示

## 风险与控制

### 风险

- SDK 黑名单方法名与当前联系人页使用风格不完全一致
- Pad 端入口可能涉及现有 `PagePad` / `HomePagePad` 的双层导航组织

### 控制

- 实现时先以现有好友页为模板
- 对黑名单操作做局部接入，不连带重构整个联系人体系
- Pad 端只补入口，不改变现有主布局结构

## 推荐实施顺序

1. 注册好友页与黑名单页路由
2. 手机端功能列表增加两个入口
3. Pad 端功能区和快捷区增加入口
4. 好友页增加 `加入黑名单`
5. 新建黑名单页并接入真实黑名单数据
6. 补充 widget tests
